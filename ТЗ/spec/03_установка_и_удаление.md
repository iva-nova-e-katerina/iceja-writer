# 3. Установка и удаление (portable)

## 3.1. Общие требования

УСТ-01. Поставка — один файл `iceja-writer.jar`. JRE не устанавливается.

УСТ-02. Установка выполняется запуском этого JAR в режиме `--install` (графический мастер). Писатель без IT-подготовки должен справиться без инструкции; Руководство пользователя — справочная поддержка, а не обязательное условие.

УСТ-03. Деинсталляция выполняется режимом `--uninstall` или пунктом меню «Помощь → Удалить программу». После удаления от Программы не остаётся следов (см. АРХ-05).

## 3.2. Проверка JRE

УСТ-10. Перед установкой и при запуске Программа проверяет наличие Java версии **25 и новее** (в `PATH`, затем `JAVA_HOME`).

УСТ-11. Если JRE не найдена или версия ниже требуемой — показывается понятное сообщение (на языке пользователя, RU/EN) с объяснением и указанием, где получить JRE 25 LTS (например, Temurin или OpenJDK). Установка при этом не выполняется и система не изменяется.

## 3.3. Мастер установки (не более 4 шагов)

УСТ-20. **Шаг 1 — Приветствие.** Название Программы, краткое описание, лицензия MIT (бесплатное распространение, текст лицензии прилагается). Язык мастера — по локали ОС (русский/английский), с возможностью переключения.

УСТ-21. **Шаг 2 — Каталог установки.** Поле выбора каталога (по умолчанию: рядом с JAR-файлом, либо `$HOME/IceJAWriter`). Установка в системные каталоги (например, `C:\Windows`, `/usr`) запрещена.

УСТ-22. **Шаг 3 — Установка.** Выполняется:

1. создание каталогов `config/`, `projects/`, `logs/`;
2. копирование `iceja-writer.jar`;
3. создание скриптов запуска `iceja-writer.sh` (Linux/macOS) и `iceja-writer.bat` (Windows) в зависимости от ОС;
4. создание файла настроек `config/app.json` со значениями по умолчанию;
5. запись журнала `logs/install.log`.

Действия обратимы и не затрагивают систему вне каталога установки.

УСТ-23. **Шаг 4 — Завершение.** Сообщение об успехе, кнопки «Запустить IceJA Writer» и «Закрыть».

УСТ-24. На Linux опционально предлагается создать ярлык приложения (`.desktop`-файл) на рабочем столе — только по явному согласию пользователя, с возможностью отказа.

## 3.4. Деинсталляция

УСТ-30. Режим `--uninstall`: диалог подтверждения («Программа и её настройки будут удалены»).

УСТ-31. Если внутри каталога установки найдены файлы проектов (`*.ijw`, включая `projects/`), выводится предупреждение «Будут удалены ваши проекты» со списком файлов; удаление продолжается только после явного подтверждения.

УСТ-32. Выполняется удаление каталога установки целиком. По завершении — сообщение о результате. Если каталог занят (Программа запущена) — понятное сообщение с объяснением.

## 3.5. Обновление

УСТ-40. Установка поверх существующего каталога (обновление): JAR и скрипты перезаписываются; `config/app.json` и `projects/` сохраняются. Перед обновлением создаётся резервная копия JAR.

## 3.6. Приёмочные критерии раздела

| Критерий | Значение |
|---|---|
| Установка на чистой ОС (Linux/Windows) с JRE 25 | не более 5 действий пользователя |
| Деинсталляция | не более 3 действий |
| Следы после деинсталляции | отсутствуют (кроме временных файлов ОС) |
| Работа без сети/интернета при установке | полностью (установка офлайн) |
| Повторная установка после удаления | возможна в любой момент |
