# 2. Архитектура и портативность

## 2.1. Единый portable-артефакт

АРХ-01. Поставка состоит из **одного файла** `iceja-writer.jar` (self-contained JAR). Этот же файл выполняет три роли:

- запуск без аргументов — запуск приложения;
- режим `--install` — запуск мастера portable-установки;
- режим `--uninstall` — деинсталляция.

АРХ-02. JAR зависит только от JRE (Java SE 25 LTS или новее). Все сторонние библиотеки упакованы внутрь JAR; отдельный каталог `lib/` не создаётся.

## 2.2. Технологический стек

| Уровень | Решение | Обоснование |
|---|---|---|
| Язык | Kotlin 2.4.x (последняя стабильная версия) | Требование проекта |
| Платформа | Java SE 25 (LTS) | Требование проекта |
| GUI | Swing, светлая тема, системный Look&Feel | Отсутствие внешних зависимостей |
| Сборка | Maven | Требование проекта |
| HTTP | `java.net.http.HttpClient` (встроен в JDK) | Минимум зависимостей |
| ZIP | `java.util.zip` (встроен в JDK) | Минимум зависимостей |
| JSON | `org.json` (единственная сторонняя библиотека) | Простота |
| DOCX | Собственный генератор OOXML | Минимум зависимостей (см. ФР-94) |

АРХ-03. Полный список сторонних зависимостей фиксируется в `pom.xml` и не должен превышать: `kotlin-stdlib`, `org.json` (и, при обоснованной необходимости, библиотека генерации DOCX, упакованная в тот же JAR). Добавление любой новой зависимости — отдельное осознанное решение.

## 2.3. Модули приложения

| Модуль | Ответственность |
|---|---|
| `model` | Доменная модель: роман, библия (7 разделов), карточки сцен, сцены |
| `project` | Чтение/запись `.ijw`, валидация, резервные копии, атомарная запись |
| `llm` | Провайдеры OpenAI/Anthropic/Custom, загрузка списка моделей, генерация, протокол изменений, проверки |
| `export` | Сборка и запись DOCX |
| `ui` | Главное окно, диалоги, локализация RU/EN, зум 75–300% |
| `install` | Установка, деинсталляция, проверка JRE, создание скриптов запуска |

## 2.4. Структура каталога установки

После portable-установки в выбранном каталоге (`IceJAWriter/` по умолчанию):

```
IceJAWriter/
├── iceja-writer.jar        — само приложение
├── iceja-writer.sh         — скрипт запуска (Linux/macOS)
├── iceja-writer.bat        — скрипт запуска (Windows)
├── config/
│   └── app.json            — настройки приложения (включая подключение к LLM)
├── projects/               — каталог проектов по умолчанию (*.ijw)
└── logs/
    ├── app.log             — журнал приложения
    └── install.log         — журнал установки
```

АРХ-04. Программа не записывает данные за пределами каталога установки, кроме временных файлов ОС (`java.io.tmpdir`) и файлов, явно выбранных пользователем (например, проект `.ijw` в произвольном месте, экспортированный `.docx`).

АРХ-05. Полное удаление = удаление каталога установки. После деинсталляции от Программы не остаётся: записей реестра, служб, задач планировщика, элементов автозагрузки, файлов в домашнем каталоге пользователя.

## 2.5. Хранение данных

АРХ-10. **Источник истины проекта — файл `.ijw`** (см. раздел 4). СУБД не используется. При открытии проект целиком читается в память; при сохранении `.ijw` перезаписывается атомарно.

АРХ-11. Настройки приложения хранятся в текстовом файле `config/app.json` (UTF-8): язык интерфейса, масштаб, интервал автосохранения, каталог проектов по умолчанию, число резервных копий, настройки LLM.

АРХ-12. Внутренние кэши и индексы (поиск, статистика) существуют только в памяти в рамках сеанса; на диск не пишутся.

## 2.6. Совместимость со сторонними инструментами

АРХ-20. Форматы данных выбираются так, чтобы проект оставался читаемым без Программы:

- `.ijw` — обычный ZIP: открывается любым архиватором;
- тексты сцен — Markdown (совместимы с Obsidian и др.);
- библия и карточки — JSON (разбираются любыми средствами).

АРХ-21. Программа не устанавливает и не запускает сторонние инструменты; пользователь может применять их отдельно (Obsidian + Dataview, Scrivener, Notion, RAG-системы и т. п.) — ограничением это не является.

## 2.7. Журналирование

АРХ-30. Приложение ведёт журнал `logs/app.log` (ротация по размеру): запуски, открытия/сохранения проектов, ошибки, статусы LLM-запросов (без содержимого промптов и без API-ключей).
