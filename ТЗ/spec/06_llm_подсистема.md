# 6. LLM-подсистема

Настоящий раздел описывает конвейер генерации по методологии `концепт.docx`. Приоритеты: **P0** — обязательный минимум первой версии, **P1** — обязательный конвейер, **P2** — вспомогательные функции.

## 6.1. Подключение к провайдеру (P0)

| ID | Требование |
|---|---|
| LLM-01 | Поддерживаются три типа провайдеров: **OpenAI**, **Anthropic**, **Свой провайдер** (OpenAI-совместимый API с произвольным базовым URL, например DeepSeek `https://api.deepseek.com/v1`). |
| LLM-02 | Поля вкладки «LLM» диалога «Настройки»: тип провайдера (выпадающий список); базовый URL (предзаполняется по провайдеру, редактируется); API-ключ (скрытый ввод с кнопкой «показать/скрыть»); модель (выпадающий список, см. LLM-03); параметры генерации: температура, максимальное число токенов, таймаут; кнопки «Загрузить список моделей», «Проверить соединение». |
| LLM-03 | **Обязательный список моделей.** Пользователь не вводит название модели вручную: приложение запрашивает у провайдера актуальный список моделей и показывает его в выпадающем списке. Запросы: OpenAI/Свой: `GET {base}/models` (заголовок `Authorization: Bearer <ключ>`); Anthropic: `GET {base}/v1/models` (заголовки `x-api-key`, `anthropic-version`). |
| LLM-04 | Ошибка загрузки списка (неверный ключ/URL, нет сети) — понятное сообщение с причиной; список моделей не подменяется, поле «Модель» остаётся неактивным до успешной загрузки. |
| LLM-05 | Список моделей кэшируется на время сеанса; кнопка «Обновить» повторяет запрос. Кнопка «Проверить соединение» выполняет контрольный запрос к API и показывает результат. |

Безопасность ключа: ключ хранится в `config/app.json` (POSIX-права 600); не сохраняется в `.ijw`; не выводится в логи; в интерфейсе маскируется.

## 6.2. Сборка контекста и промпты (P1)

| ID | Требование |
|---|---|
| LLM-10 | Перед генерацией собирается **курированный контекст**, а не весь роман: срез библии (мир, релевантные персонажи с голосами, срез хронологии, правила, стиль), резюме предыдущей сцены (`summary`), карточка текущей сцены, ограничения объёма. |
| LLM-11 | Размер контекста ограничивается настраиваемым лимитом токенов (по умолчанию 16 384); сборщик сокращает контекст по приоритету: карточка сцены → стиль → резюме предыдущей сцены → срез библии. |
| LLM-12 | Шаблоны промптов — ресурсы приложения с плейсхолдерами (`{context}`, `{card}`, `{style}`…). Редактирование шаблонов пользователем — перспектива. |

## 6.3. Генерация черновика сцены (P1)

| ID | Требование |
|---|---|
| LLM-20 | Команда «Сгенерировать черновик» для выбранной сцены: модель пишет черновик объёмом 800–1500 слов (по умолчанию; границы берутся из `wordTargetMin/Max` карточки); POV, время и стиль — из карточки и `bible/style.json`; новые важные факты модель помечает `[NEW]`. |
| LLM-21 | Запрос выполняется асинхронно (UI не блокируется): индикатор прогресса, кнопка «Отмена», таймаут из настроек, до 2 автоматических повторов при сетевых ошибках, понятные сообщения об ошибках. |
| LLM-22 | Результат показывается в панели «Черновик» (рядом с карточкой) и **не записывается в текст сцены автоматически**. Кнопки: «Принять» (записывает в текст сцены), «Править вручную», «Запросить альтернативу», «Отклонить». |
| LLM-23 | Альтернативы: до 3 вариантов черновика; каждый сопровождается собственным протоколом изменений. |

## 6.4. Протокол изменений (P1)

| ID | Требование |
|---|---|
| LLM-30 | Вместе с черновиком модель возвращает структурированный протокол изменений (JSON): `newFacts[]` (новые факты), `stateChanges[]` (изменения состояния), `openQuestions[]` (открытые вопросы), `contradictions[]` (возможные противоречия). |
| LLM-31 | Протокол показывается отдельной панелью рядом с черновиком. |
| LLM-32 | Кнопка «Добавить в библию» — по пунктам протокола, с выбором раздела библии (персонажи/хронология/правила/…). **Автоматическое изменение библии запрещено**: канон обновляется только после явного подтверждения автором. |

## 6.5. Проверки — «редактор-континуист» (P2)

| ID | Требование |
|---|---|
| LLM-40 | Диалог «Проверки»: выбор типа проверки (continuity, логика, хронология, знание персонажей, стиль/анахронизмы, сюжетные дыры) и диапазона (глава / акт / весь роман). |
| LLM-41 | Модель возвращает **только список проблем** с указанием сцен и фактов; текст не переписывается. |
| LLM-42 | Двойной клик по пункту проблемы открывает соответствующую сцену. |

## 6.6. Резюме сцен (P2)

| ID | Требование |
|---|---|
| LLM-50 | После утверждения сцены генерируется её резюме (2–5 предложений) и сохраняется в `summary` карточки. |
| LLM-51 | Резюме предыдущей сцены автоматически включается в контекст генерации следующей (см. LLM-10). |

## 6.7. Приоритеты внедрения

| Фаза | Требования |
|---|---|
| P0 (настройки) | LLM-01…LLM-05 — подключение, список моделей, проверка соединения |
| P1 (конвейер) | LLM-10…LLM-12, LLM-20…LLM-23, LLM-30…LLM-32 |
| P2 (качество) | LLM-40…LLM-42 (проверки), LLM-50…LLM-51 (резюме) |

## 6.8. Ограничения

- Модель никогда не решает канон; автор утверждает всё вручную.
- В «О программе» и Руководстве — правовое примечание: текст, полностью сгенерированный AI, может не охраняться авторским правом; издательства могут требовать раскрытия использования AI.
