# 1. Общие сведения

## 1.1. Наименование программного обеспечения

**IceJA Writer** (далее — «Программа», «приложение»).

## 1.2. Назначение

IceJA Writer — настольное программное обеспечение для упрощения написания художественных произведений, прежде всего романов объёмом до 600 страниц (≈ 150 000 слов).

Программа реализует метод «шоураннера», описанный в `концепт.docx`: автор управляет сюжетом, каноном и структурой, а языковая модель (LLM) используется как быстрый «чернорабочий» — генератор черновиков сцен, диалогов, описаний и вариантов по карточкам сцен.

## 1.3. Основание для разработки

1. `техническоезадание.txt` — требования заказчика.
2. `концепт.docx` — методология работы с LLM при написании романа.

## 1.4. Цели создания

1. Структурированное ведение проекта романа: описание (сюжет), «Библия романа», карточки сцен, тексты сцен — в едином файле проекта `.ijw`.
2. Автоматизация черновой работы с помощью LLM: генерация черновиков сцен по карточкам, альтернативные варианты, протокол изменений, проверки канона.
3. Простое распространение и удаление: portable-установка одним JAR-файлом без СУБД и без фоновых сервисов; с установкой и удалением должен справиться писатель без IT-подготовки.
4. Экспорт готового романа в формат Microsoft Word (.docx).

## 1.5. Целевая аудитория

Писатели художественной литературы, в том числе непрофессионалы. Интерфейс, установка и удаление не должны требовать специальных знаний.

## 1.6. Границы проекта

- Максимальный объём проекта: роман до 600 страниц (принято расчётное значение 150 000 слов).
- JRE (Java Runtime Environment) **не** входит в поставку и не устанавливается Программой. Требуется Java SE 25 (LTS) или новее.
- Программа **не** устанавливает и не запускает сторонние инструменты (Obsidian, Scrivener, Notion, RAG-системы и т. п.). Обеспечивается только совместимость форматов с ними (человекочитаемые текстовые файлы, Markdown).
- Программа не создаёт СУБД, служб ОС, записей в реестре и элементов автозагрузки.

## 1.7. Термины и сокращения

| Термин | Определение |
|---|---|
| `.ijw` | Файл проекта IceJA Writer — ZIP-архив с текстовыми данными проекта |
| Библия романа | Рабочая база канона: мир, персонажи, хронология, правила, сюжетные линии, глоссарий, стиль |
| Карточка сцены | Структурированное описание одной сцены: POV, место, время, цель, конфликт, поворот и т. д. |
| Протокол изменений | Структурированный результат генерации: новые факты, изменения состояния, открытые вопросы, возможные противоречия |
| POV | Точка зрения (point of view), от чьего лица написана сцена |
| LLM | Большая языковая модель (Large Language Model) |
| OpenAI-совместимый API | Формат REST-API вида `/v1/chat/completions` и `/v1/models`, используемый многими провайдерами |
| Portable | Переносимая установка: все файлы Программы в одном каталоге, без следов в системе |
| JRE / JVM | Среда выполнения Java |
| DOCX | Формат документов Microsoft Word (OOXML) |

## 1.8. Принципы, обязательные для реализации

1. **Минимум сторонних компонентов.** В идеале всё приложение — один JAR-файл; все используемые библиотеки упакованы внутрь него. Запрещены СУБД, нативные библиотеки и внешние сервисы.
2. **Текстовое хранение.** Все данные проекта — человекочитаемые текстовые файлы (JSON, Markdown) в кодировке UTF-8.
3. **Канон решает автор.** Ни один новый факт, придуманный моделью, не попадает в библию автоматически — только после явного подтверждения автором (принцип из `концепт.docx`).
4. **Дискретные сцены вместо непрерывного текста.** Работа идёт по сценам с карточками и обновлением состояния, а не «напиши главу целиком».
5. **Простота для непрофессионала.** Установка, удаление и повседневная работа должны быть понятны человеку без технического образования.
6. Соблюдение принципов SOLID, DRY, KISS при разработке.
