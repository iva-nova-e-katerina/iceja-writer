# 9. Критерии приёмки, этапы, открытые вопросы

## 9.1. Критерии приёмки по исходному ТЗ

| Пункт исходного ТЗ | Критерий приёмки |
|---|---|
| 1. Portable JAR инсталлятора/деинсталлятора, кроме JRE; простота для писателя | Установка на чистой ОС с JRE 25 — не более 5 действий; деинсталляция — не более 3 действий; после деинсталляции следов нет; JRE не устанавливается (УСТ-01…УСТ-32) |
| 2. Открытие/редактирование/сохранение проекта `.ijw` (ZIP): а) описание ≤ 2 КБ; б) библия; в) карточки сцен; г) тексты сцен | Проект создаётся, открывается, редактируется и сохраняется; внутри архива все четыре группы данных по структуре раздела 4; описание блокируется при превышении 2048 байт (ФР-01…ФР-52, ФРМ-01…ФРМ-32) |
| 3. Минимум сторонних компонентов, portable, легко удаляемое | Поставка — один JAR; зависимостей по АРХ-03; нет СУБД/служб/реестра; удаление каталогом (АРХ-01…АРХ-05) |
| 4. Диалог «Настройки» с подключением к LLM и другими настройками | Диалог есть; провайдеры OpenAI/Anthropic/Свой; модель выбирается из списка, полученного от провайдера (LLM-01…LLM-05); прочие настройки по ФР-101 |
| Доп. Экспорт романа в Word (.docx) | Файл открывается в LibreOffice Writer и MS Word; порядок сцен и заголовки корректны; кодировка без искажений (ФР-90…ФР-95) |
| Доп. Полный LLM-конвейер из концепта | Генерация черновика по карточке, альтернативы, протокол изменений, проверки, резюме (раздел 6) |

## 9.2. Этапы разработки

| Этап | Содержание | Результат |
|---|---|---|
| Э1. Каркас и формат | Главное окно, меню, локализация RU/EN, зум 75–300% (частично готово); чтение/запись/валидация `.ijw`; редакторы описания (2 КБ), библии, карточек, текстов; автосохранение; поиск; статистика | Можно вести проект романа без LLM |
| Э2. LLM-конвейер | Настройки провайдеров, список моделей из API, генерация черновика, протокол изменений, альтернативы | Рабочий конвейер генерации (P0+P1) |
| Э3. Качество и экспорт | Проверки-континуист, резюме сцен; экспорт в DOCX | Полный функционал приложения |
| Э4. Распространение | Установщик/деинсталлятор (`--install`/`--uninstall`), проверка JRE, скрипты запуска; Руководство пользователя; приёмочные испытания на чистых ОС | Готовый portable-продукт |

Рекомендация из методологии: перед полномасштабной работой провести «пилот» — один роман, 10–15 сцен через весь конвейер, затем масштабировать.

## 9.3. Открытые вопросы и риски

| Вопрос | Статус |
|---|---|
| Шифрование API-ключа (сейчас — файл с правами 600) | Требует решения заказчика |
| Тёмная тема интерфейса | Перспектива |
| Уровни «цикл/арка серии/бит» (ФР-61) | Перспектива |
| Локальные LLM (Ollama и т. п.) | Частично покрывается «Своим провайдером» (OpenAI-совместимый endpoint) |
| Git-версионирование проектов | Перспектива; пока — резервные копии `.bak-N` |
| Правовые аспекты AI-текста (авторское право, раскрытие использования AI) | Дисклеймер в «О программе» и Руководстве (НФР-14) |

### Приложение В. Шаблон промпта генерации (по методологии)

> Ты — соавтор. Контекст: {фрагменты библии}. Предыдущая сцена: {резюме}.
> Карточка сцены: {карточка}. Напиши черновик сцены, {объём} слов.
> Сохраняй POV, время, стиль. Не добавляй новых важных фактов без пометки [NEW].
> В конце выведи JSON: новые факты, изменения состояния, открытые вопросы, возможные противоречия.

### Приложение Г. Шаблон промпта проверок (по методологии)

> Ты — редактор-континуист. Найди противоречия между новым текстом и этими фактами: {факты библии}.
> Тип проверки: {continuity | логика | хронология | знание персонажей | стиль | сюжетные дыры}.
> Не переписывай, только список проблем с указанием сцен и фактов.
